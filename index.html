🗺 How to read an InSAR product from HyP3

Interferometric phase — rainbow colour cycle
−π0+π

Each colour cycle = one radar wavelength of LOS change (~5.6 cm for C-band). Fringes = deformation or atmospheric signal. Dense fringes near 0 = more change than widely spaced.

Coherence — greyscale 0→1
0 · no correlation1 · perfect

Dark = decorrelated (vegetation, wet soil, surface change, steep terrain). Bright = stable, coherent. Always check coherence before interpreting phase. Low coherence = phase noise, not displacement.

Temporal decorrelation

Vegetation, monsoon moisture and surface change between acquisitions can destroy phase quality. The Himalaya is especially vulnerable. Check coherence first.

Atmospheric signal

Tropospheric water vapour differences can appear as systematic phase ramps, mimicking deformation. A single interferogram cannot separate deformation from atmosphere.

LOS ≠ slope displacement

The displacement map assumes deformation is vertical. Real slope movement is complex. Geometry, look angle and incidence direction all affect the observed signal.

Layover and shadow

Steep Himalayan slopes facing or away from the radar may appear layered or invisible. These are geometry artefacts, not deformation patterns.

HIMGAURAV does not change slope state from InSAR alone. Interferograms are research evidence. Warning state requires validated rainfall threshold exceedance plus field-confirmed inclination anomaly.
ASF automation — real subscription-like workflow

ASF no longer provides the old subscription feature directly; its current documentation recommends building subscription-like workflows with ASF search + HyP3. HIMGAURAV includes a discovery cycle and a scheduler-ready helper script. It never consumes HyP3 credits automatically unless you explicitly enable auto-submit in .env.

Discovery only by default
InSAR interpretation boundary: line-of-sight phase change is not the same as downslope displacement. Coherence loss, vegetation, atmosphere, steep Himalayan geometry and fast failure can invalidate or hide deformation. HIMGAURAV therefore shows product provenance, coherence and processing metadata before any displacement interpretation.

Why this uses inclination instead of claiming seismic detection

The existing project correctly rejects STA/LTA on a cloud stream sampled roughly every 15 seconds: the waveform needed for seismic onset detection is gone before the browser receives it. The current node therefore treats slow inclination as the honest browser-visible measurement and estimates its baseline/noise from its own history.

The anomaly rule is preserved: sustained displacement beyond max(3 × measured noise, 0.05°) for three samples. It is an engineering trigger, not a validated landslide classifier, and can only confirm a rainfall WATCH — it cannot create WARNING by itself.

      What your results may legitimately be compared with

      Published numbers below are context anchors, not automatic acceptance limits. Your node must be judged from its own reference measurements, uncertainty, repeatability and deployment conditions.

      Himalayan slope sensingPublished Darjeeling/Kalimpong work combines rainfall, MEMS tilt and volumetric water content rather than relying on rainfall alone.This supports evidence fusion, not transfer of their thresholds to Sundernagar.

      CAL-01 · MPU6500

      Static inclination calibration

      REFERENCE ANGLE

      Mount the node rigidly. Apply known angles with a digital inclinometer/reference level. Record reference angle and node angle at each step after settling. Repeat in both directions if possible.

      Add ≥2 calibration points to see the reference vs node scatter with identity line.
      CAL-02 · SOIL MOISTURE

      Gravimetric / volumetric calibration

      SOIL-SPECIFIC

      Use soil from the installation site. Record sensor raw value, wet mass, oven-dry mass and known sample volume. HIMGAURAV calculates gravimetric water content and volumetric water content for a soil-specific calibration curve.

      Hold-out rule: fit the calibration relation only on samples marked Calibration. Samples marked Held-out validation are used to calculate independent prediction error and are never used to fit the line.
      Add ≥2 samples to see raw ADC vs VWC% calibration curve.
      CAL-03 · RAIN

      Rain detector / tipping-bucket validation

      WMO-STYLE COMPARISON

      A wet/dry board can validate rain occurrence only. For rainfall in millimetres, use a manual gauge or tipping bucket. For a tipping bucket, enter collector area, applied water volume and counted tips to estimate mm per tip.

      CAL-04 · LoRa

      Radio reliability trial

      LINK QUALITY

      Run a fixed packet test at a known location/distance. Record transmitted, received, RSSI, SNR and latency. There is no universal “good” threshold; report the measured PDR and conditions.

      LIMITATIONS

      What the prototype does not claim

      • Open‑Meteo values are numerical weather-model estimates on a grid, not IMD rain-gauge observations.
      • The rainfall threshold was fitted for Shimla. Using it at Kotrupi, Mandi, Kullu, Dharamshala or Solan is an extrapolation and the interface labels it as such.
      • A threshold exceedance is a screening condition, not a landslide prediction or probability of failure.
      • One ThingSpeak node is a student deployment/instrument demonstration, not a certified life-safety early-warning system.
      • Seismic events are contextual only. Regional catalogue completeness cannot detect a single slope starting to fail.
      • Browser notifications, local speech and siren tests are operator-device outputs only. Public SMS / Cell Broadcast remains outside the prototype unless an authorised agency connector is configured.
